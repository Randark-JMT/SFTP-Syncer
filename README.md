# SFTP Syncer

一个使用 Go + Wails + React 编写的 Windows 桌面 SFTP 同步工具，支持多主机管理与并行同步。

## 技术栈

- 后端：Go（`internal/syncer` 同步引擎、`internal/config` 配置持久化）
- 前端：React + TypeScript + Ant Design 5（Vite 构建）
- 框架：[Wails v2](https://wails.io)（WebView2）
- 系统托盘：[fyne.io/systray](https://github.com/fyne-io/systray)

## 功能

- **主机管理器**：添加主机后参数自动记忆（持久化到用户配置目录），左侧栏以卡片方式管理多台主机；添加/编辑使用右侧滑出抽屉，支持按名称/地址搜索
- **多主机并行同步**：可单独开始/停止某台主机，也可「全部开始/全部停止」，各主机拥有独立的连接与下载 Worker 池（10 Worker），互不干扰
- 支持选择 **密码认证** 或 **私钥认证**（私钥口令可选），可跳过或启用主机密钥校验
- 支持通过 **HTTP / HTTPS / SOCKS5 代理** 连接主机，代理可选用户名+密码认证
- 递归扫描远程目录，并保留原有目录结构下载到本地
- 枚举时跳过以点（`.`）开头的目录（如 `.git`、`.ssh`），整个子树不做扫描；远程根目录本身以点开头时不受影响
- 仅处理 **远程文件 UTC 修改时间早于当前时间 30 分钟** 的常规文件；根目录下的散文件跳过
- 下载成功后删除远程源文件
- **任务页**：按主机显示每个文件的下载状态、进度条与速度，事件实时推送
- **日志页**：按级别着色（错误红 / 警告橙 / 成功绿 / 信息默认色），支持级别筛选、暂停自动滚动与清空，保留最近 500 条
- **明暗主题**：跟随偏好切换，状态实时刷新
- 下载使用带 io.ReadFull 语义的并发分块传输，容忍服务器的短读（short read）
- 点击窗口关闭按钮后隐藏到系统托盘：左键托盘图标恢复窗口，右键菜单可退出

## 使用说明

1. 启动程序后点击左侧「添加主机」，在抽屉中填写：
   - 名称（可选，用于区分主机）
   - 服务器地址、端口、用户名
   - 认证方式：密码 或 私钥
   - 远程目录、本地目录（可通过按钮调起系统目录选择框）、轮询间隔（秒）
   - 如需跳过主机密钥校验，保持「跳过」开关打开
   - 如需经代理连接，选择「连接代理」类型（HTTP / HTTPS / SOCKS5）并填写代理地址与端口；代理认证的用户名、密码可留空
2. 点击「确定」后主机即保存并出现在左侧列表；运行中的主机需先停止才能编辑或删除
3. 点击主机卡片上的「开始」立即执行一轮扫描并按轮询间隔持续运行；「全部开始」可同时启动所有主机
4. 右侧「下载任务」页实时显示各主机当前下载任务；「运行日志」页按主机前缀记录运行情况
5. 点击窗口右上角关闭按钮时，程序隐藏到系统托盘（最小化保留在任务栏）：
   - 左键托盘图标：恢复窗口
   - 右键托盘图标：显示主窗口 / 退出程序

## 配置文件位置

程序会把主机列表保存到用户配置目录下：

- Windows：`%AppData%\SFTP-Syncer\hosts.json`

> 旧版本的单主机 `config.json` 会在首次启动新版本时自动迁移为 `hosts.json` 中的一条主机记录，原文件保持不变。

> 当前版本会把密码或私钥相关配置保存到本地配置文件中，以便下次启动自动填充。若你对安全要求较高，建议后续改造为 Windows Credential Manager 或更安全的密钥托管方式。

## 开发

环境要求：Go 1.24+、Node 20+、[Wails CLI](https://wails.io/docs/gettingstarted/installation)。

```bash
# 安装 Wails CLI（国内网络建议先设置 GOPROXY）
go install github.com/wailsapp/wails/v2/cmd/wails@latest

# 开发模式（热重载，自动打开窗口）
wails dev

# 生产构建（产物在 build/bin/SFTP-Syncer.exe）
wails build
```

版本号独立定义在 `version.go` 的 `Version` 变量中（默认值为 `dev`），构建时可通过 ldflags 覆盖：

```bash
wails build -ldflags "-X main.Version=v1.0.0"
```

也可以通过 GitHub Actions 手动触发 **Release** 工作流（`workflow_dispatch`），输入版本号后会自动编译 Windows 可执行文件并发布对应的 GitHub Release。

## 备注

- 主机时间判断统一使用 UTC。
- 为避免与远程仍在写入的文件竞争，程序只会处理早于当前时间 30 分钟的文件。
- 如果下载成功但远程删除失败，该文件会保留在本地，下一轮仍可能再次尝试处理远程文件。
- 下载链路针对吞吐做了调优：SFTP 读包大小 256KB、单文件最多 256 个并发读请求，在高延迟链路上也能跑满带宽；分块读取采用 io.ReadFull 语义，能正确处理服务器返回的短读。
- 运行时依赖 WebView2 运行时（Windows 11 已预装；Windows 10 通常由 Edge 更新自动安装）。
